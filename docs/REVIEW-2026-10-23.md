# Deep static review — 2026-10-23

The live attack battery could not be executed from the agent
environment (platform safety layer), so at the owner's direction the
assurance was produced statically instead: several full passes over
the shipped code — logic, state machines, arithmetic — with every
finding either fixed, or recorded here with its disposition.
Scenario-level simulations of the real scoring functions
(`tests/unit/test-scoring-scenarios.sh`) stand in for the traffic
tests.

## Pass 1 — auto-ban daemon

- **R-1 (checked, OK):** double enforcement in one cycle (REP-BAN then
  INSTANT path) is harmless: `ban_ip` is state-guarded, `rep_on_ban`
  idempotent.
- **R-2 (Medium, FIXED):** auto-release fired on a *single* quiet
  sample and called `clear_reputation` — a pulsing source (hot 40 s /
  quiet 3 s) wiped its score history every cycle and could never
  accumulate consequences. Release is now gated on the score having
  recovered to the throttle band or better; the entry is left to the
  sweep's time-based recovery.
- **R-7 (Medium, FIXED):** `hard_throttle_ip` deleted and re-added
  the tc filter on *every* scoring cycle (filter churn, a prio burned
  per cycle, log spam), while the v6 enforcer could *never* upgrade
  soft→hard. Both are now band-aware: same band = no-op, upgrade =
  replace.
- **R-13 (Low, FIXED):** `self_guard` removed kernel DROP rules for
  own IPv4 addresses but left the BANNED_LIST entry (the v6 half
  already purged it). Now symmetric.
- **R-15 (Medium, FIXED):** `ban_subnet`'s whitelist guard compared
  only first-3-octets — a whitelisted `x.y.0.0/16` (or any CIDR not
  starting at the /24 boundary) did **not** protect its /24s, and the
  subnet DROP is inserted at the top of INPUT, *above* the whitelist
  ACCEPTs — a live FR-1 violation path. The guard is now a true CIDR
  overlap test (both directions), the same idiom as the CF check.
- **R-17 (Low, FIXED):** `ban_subnet` recorded state even when the
  iptables insert failed (the BUG-024 anti-pattern). State now
  follows success, with a loud failure log.
- **R-12 (Info):** ban expiry granularity is ~5 min (every 75 cycles)
  beyond the configured duration — documented behaviour, accepted.

## Pass 2 — rule/script generators

- **R-18 (Medium, FIXED):** the generated `tc-setup.sh` restored
  daemon throttles with IPv4 syntax only — after a reboot, IPv6
  throttle filters were silently lost when the qdisc was rebuilt by
  the persistence service (the daemon's own re-apply is family-aware;
  the generated script now is too).
- **R-21 (Medium, FIXED):** the HTB tree was hardcoded to 1 Gbit.
  HTB shapes only when its rates are the bottleneck — on a 200 Mbit
  VPS the qdisc never engages, and a "100 Mbit throttle" is fiction.
  `setup_tc` now detects the link speed (`/sys/class/net/<if>/speed`)
  and scales the tree preserving the designed ratios (default S/2,
  throttle S/10, hard S/20); the generated persistence script is
  scaled identically. At 1 Gbit the values are unchanged.
- **R-20 (Info):** IPv6 entries in the v4 tc whitelist loops produce
  harmless, swallowed tc errors; left as-is.

## Pass 3 — 3proxy / sysctl / menu / installer

Re-verified against Waves 6–8 fixes and the two live installs
(Debian 12 + Ubuntu 26.04, incl. the T-3 GCC-15 build fallback and
the T-1 fail2ban journal handling). No new defects found; the
uninstall path remains covered by the Wave-6 regression guards
(it has never been live-tested — noted honestly).

## Pass 4 — scoring mathematics (simulated trajectories)

`test-scoring-scenarios.sh` drives the shipped `update_score` /
`reputation_sweep` through minute-by-minute scenarios with simulated
time: net-growth churn (EWMA warm-up behaves as designed), burst-then-
quiet full recovery, SYN-heavy path to the ban band in ~5 min,
probation relapse costing double, probation quiet reaching 100 in
~6 min, single-sample spike costing ~1–5 points (no cliff), steady
250-conn bleed at the designed slow rate. **8/8 pass.** Known model
limits are documented in `docs/SCORING.md` (turnover blindness,
top-100 sampler, NAT sharing).
